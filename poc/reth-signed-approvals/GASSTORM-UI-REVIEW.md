**Historical review — superseded by the [stability report](STABILITY-REPORT.md) and [current review](STABILITY-REVIEW.md).** The earlier capacity screenshots below contain nonce gaps and are not valid capacity claims. The launcher now applies tested patches in isolated clones.

| Checked | Result |
|---|---|
| UI launcher | `gasstorm.sh ui` builds the unmodified sibling dashboard and starts isolated OPS, PostgreSQL, Redis, custom Reth and the actual Go load generator. Transaction traffic goes through OPS. The Python control adapter only configures tests, refreshes development login and reports node queue counts. |
| Configuration | Ten funded wallets with actual wallet-link signatures and DB grants. Real deployed Gasstorm contracts. One-second block scheduling, 200M gas/block, 4,096 Reth RPC connections and OPS pools of 1,024 connections per upstream client. Both modes use these settings. |
| Fixtures | Development identity-provider login and local Engine API scheduling. No indexer or external blockbuilder. UI Load Test and History work; unrelated L1/L2 WebSocket indicators remain red. |
| TDD | Configuration tests first failed without the normalizer, then passed. A second red/green check rejects the UI's `fixNonceGaps` option: this loadgenerator checkout defines the field and healer package but never starts that healer. [Red](evidence/gasstorm-ui/red-nonce-toggle.log), [green](evidence/gasstorm-ui/green-config.log). |
| Real browser | Chrome/Playwright selects Privacy Proxy and Adaptive through normal UI controls. It checks live WebSocket metrics, adaptive rate changes, completion, actual workload and ten-wallet configuration. Screenshots are unaltered browser captures. |
| Receipt verification | After each timed run, look up every unique logged transaction hash directly on Reth. Record successful and missing receipts separately; require zero reverted receipts. `PASS` in capacity capture means the capture and verification completed, not that all submissions succeeded. |
| Completed validation | Four fresh 120-second browser runs completed; 530,537 successful receipts independently checked, zero reverted receipts. Both configuration tests pass; Python compilation, JavaScript/shell syntax and whitespace checks pass. All benchmark-owned processes and containers stopped cleanly. |
| TPS interpretation | The dashboard peak is a short live measurement. HTTP sampling can miss peaks received by the UI over WebSocket; raw WebSocket frames are also saved for the last three runs. Gasstorm's final persisted `peakTps` can be lower because its backend overwrites the peak before comparing it. The screenshot retains the UI's maximum. |
| Full chart correction | `real-time-chart.tsx` displays the last 300 points with a 15-point trailing average. The completed ETH/on screenshot therefore omits the early peak. The raw WebSocket sample at 16.387 seconds reports 1,387.478 TPS. `plot_ui_run.py` exports all 600 in-duration samples and 119 actual node queue samples, with no added smoothing. [Full chart](evidence/gasstorm-ui/charts/eth-on-full-run.png). Original screenshots remain untouched. |
| Independent throughput | `analyze_ui.py` counts canonical block transactions in 30-second windows using local observation times, alongside actual Reth pending/queued counts. This is whole-stack throughput, not isolated Reth execution time. |
| ETH queue issue | With enforcement, wallet `0x15d34AAf54267DB7D7c367839AAf71A00a2C6A65` lacked nonce 4673 while 2,147 later transactions were queued. The corresponding Gasstorm log entry is discarded, with no recorded send error. No state-mismatch denial or approval-timeout event appears in this node log. The cause of the missing transaction is not isolated. [Queue](evidence/gasstorm-ui/capacity/eth-transfer-on/queued-wallets.json), [transaction logs](evidence/gasstorm-ui/capacity/eth-transfer-on/nonce-gap-logs.json). |
| Queue issue without enforcement | The ERC20 baseline also developed a missing nonce: wallet `0x976EA74026E726554dB657fA54763abd0C3a0aa9` lacked nonce 11959, with 2,472 later transactions queued. Thus nonce gaps also occur when our module is disabled. [Baseline queue](evidence/gasstorm-ui/capacity/erc20-approve-off/queued-wallets.json). |
| Reproduced sender bug | `senderWorker` immediately reuses its batch slices, but `SendBatchAsync` captures them without copying. A deterministic test with a blocked fake RPC client submits the next transaction instead of the queued original and delivers completion to the wrong callback. Copying the outer transaction and callback slices before starting the goroutine passes that regression and all five existing sender tests. This candidate is tested through a build overlay only; it is not deployed to the UI. [Red/green evidence and candidate patch](evidence/gasstorm-ui/sender-buffer-repro). This proves a defect that can create nonce gaps; the exact missing transaction in the archived run is not traced end to end. |
| User's constant 2K ETH run | Enforcement was enabled. The Engine driver timed out waiting for `engine_forkchoiceUpdatedV2`; the launcher then shut down the entire stack. The disconnected UI retained “test in progress,” making Stop/Reset ineffective. All old processes were confirmed stopped and a fresh idle session restored. The root cause of Reth's timeout is still unresolved. [Failed session logs](evidence/gasstorm-ui/interactive-20260911T194158Z/launcher.log). |
| ERC20 approval issue | The enabled run logged 39 approval timeouts and stopped making progress near its end. The store defaults to 100,000 entries; approvals arriving first remain until their 300-second cleanup deadline, including approvals for already mined transactions. This limit is a likely contributor; capacity rejection has no dedicated counter, so the exact causal chain remains unverified. No Rust changes were made to hide or bypass this limit. |
| Display limitations | OPS redacts block gas usage, so gas/fill charts show zero. The ERC20 duration input displayed zero after changing workload, while the submitted request, backend history and running timer all show 120 seconds. Actual start requests are saved as `ui-last-start.json`. |
| Driver corrections | Wall-clock block timestamps fixed the initial zero-TPS live chart. Persistent Engine/RPC connections avoid a new socket per driver call; failed connections are discarded without replaying Engine mutations. Children run in separate process groups so Ctrl+C allows ordered cleanup. The pool monitor reuses one connection rather than opening one per UI request. |
| Failed attempts | Earlier aggressive ramps hit local socket exhaustion and DB/Redis timeouts. Those attempts are retained under `evidence/gasstorm-ui/red-capacity-connections` and `capacity/incomplete-*`. Increasing connection limits alone did not resolve them. The completed runs use the documented gentler ramp and persistent driver connections. |
| Scope | Upstream Reth, sibling Gasstorm and loadgenerator stay unmodified. No policy exemptions, nonce healing or new production Go/Rust changes were added for these screenshots. Earlier correctness regressions and isolated Reth benchmarks remain documented separately. |
